# OAABH-040 Journal

Date: 2026-05-29
Task: OAABH-040 - Provider HTTP Operation Policy

## Changes

- Added `ProviderHttpOperationPolicy` to carry provider-owned retry-after,
  safe-cache, and throttle intent through each HTTP runtime request.
- Extended retry handling so retryable HTTP status failures can honor bounded
  `Retry-After` seconds while preserving the existing default retry behavior.
- Kept cache and throttle as explicit operation facts instead of adding hidden
  runtime cache state or a scheduler.
- Wired TMDB detail enrichment to declare authenticated safe-cache and
  provider-local throttle intent.
- Updated fake transport and rendered AV fixture tests to assert the policy is
  part of the runtime boundary.

## Notes

- The policy model is intentionally descriptive. It gives future host/runtime
  code a typed place to honor provider cache and throttle intent without making
  today sidecar runtime silently cache authenticated responses.
- TMDB is the initial call-site because its detail enrichment has high fan-out
  and a clear provider-local throttle/cache boundary.
