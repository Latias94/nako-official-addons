# OMASE-040 - Typed Artwork Candidate Flow

Task: promote provider image facts into typed artwork candidates and support
explicit `artwork_write` submission through the Nako runtime client.

What changed:
- Added a dedicated `engine::artwork` module for typed artwork candidate
  facts, request parsing, candidate selection, provenance, and redaction-safe
  summary shaping.
- Extended ranking response shaping so provider suggestions now carry typed
  artwork candidates alongside metadata patches.
- Promoted TMDB poster/backdrop images and Bangumi image variants into typed
  artwork candidates instead of metadata tags.
- Wired `MetadataScrapeRuntime` to submit explicit `artwork_write` requests
  through the outbound Nako runtime client when an `artwork_writeback`
  payload is present.
- Added runtime tests for `artwork_write` request shape, `media_item`
  target validation, and engine-level artwork writeback submission.
- Updated browser worker candidate identity to remain anchored to the source
  URL rather than the extraction endpoint.

Validation:
- `cargo test -p nako-metadata-scraper --lib --no-run`
- `cargo nextest run -p nako-metadata-scraper artwork side_effect --no-fail-fast`
- `cargo fmt --all -- --check`
- `cargo nextest run -p nako-metadata-scraper --no-fail-fast`
- `cargo nextest run --workspace --no-fail-fast`

Notes:
- Ordinary metadata suggestions still remain suggestion-only.
- Artwork candidates are still Nako-owned side-effect inputs, not public
  artwork inside the Addon.
- Next task is OMASE-050: evaluate the Bulk Metadata Scrape / Addon Task seam.
