# OMASE-030 - Explicit Metadata Writeback

Task: allow an explicit metadata request payload to submit the selected
candidate patch as a Nako `metadata_write` side effect when runtime writes are
enabled.

What changed:
- Added disabled-by-default Nako runtime side-effect configuration and a typed
  outbound client for `access-check` and `metadata_write` submission.
- Extended the metadata runtime with an explicit `payload.writeback` request
  path that submits the selected ranked candidate patch when configured.
- Added redaction-safe skipped/failure summaries for missing config, missing
  candidates, access-check failures, and invalid writeback payloads.
- Added smoke script support for direct explicit writeback requests and
  updated addon docs to describe the payload shape and runtime gates.

Validation:
- `cargo test -p nako-metadata-scraper --lib --no-run`
- `cargo nextest run -p nako-metadata-scraper side_effect metadata --no-fail-fast`
- `cargo nextest run -p nako-metadata-scraper --no-fail-fast`
- `cargo build -p nako-metadata-scraper`
- direct smoke on `127.0.0.1:19100`
- direct writeback smoke on `127.0.0.1:19101`
- `cargo fmt --all -- --check`
- `git diff --check`

Notes:
- Ordinary `/metadata` calls still omit `writeback` and remain suggestion-only.
- The writeback branch is opt-in, uses the top-ranked candidate patch, and
  stays redaction-safe when the runtime is disabled or the request is invalid.
