# OEAM-040 - Official Runner Materialization Client

Date: 2026-05-29

## Summary

Added the sidecar materialization client boundary needed before any production
external acquisition adapter can enqueue real material.

The shared `nako-addon-client` runtime client now exposes
`materialize_external_acquisition()`. The official fixture runner now delegates
enqueue materialization through an `ExternalAcquisitionMaterializer`
abstraction and keeps materialized URI, password, target refs, idempotency keys,
and materialization refs out of task responses.

## Changes

- Added `NakoRuntimeClient::materialize_external_acquisition()` in `../nako`.
- Added request schema and operation checks before materialization HTTP calls.
- Added runtime client tests for bearer-header auth, invalid operation
  rejection, body-token rejection, and debug redaction.
- Added runner-side `materialization` module with `nako_runtime`,
  `unavailable`, and `fixture_local` implementations.
- Added runner configuration for optional host materialization.
- Passed task `job_id` and declaration id into runner action handling.
- Materialized only during enqueue and summarized the result as safe facts.
- Preserved local smoke behavior with the default fixture-local materializer.
- Documented the optional materialization environment variables.
