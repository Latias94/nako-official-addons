# OEAM-010 - Open Materialization Workstream

Date: 2026-05-29

## Summary

Opened the `official-external-acquisition-materialization` lane as the
follow-on from `official-external-acquisition-runner`.

The core boundary is now explicit: external acquisition actions keep using
opaque target references, while a separate host-owned runtime capability will
materialize approved references for the sidecar during enqueue.

## Key Decisions

- Do not add Transmission or any other production adapter in this lane until the
  materialization contract is verified.
- Do not put raw URL/password/provider material into task input, task output,
  browser API requests, diagnostics, or logs.
- Bind materialization to action context: addon identity, task/job identity,
  declaration identity, operation, runner profile, idempotency, target ref, and
  audit ref.
- Treat this as a hard contract that needs an ADR or ADR update in OEAM-020.

## Next Task

Continue with OEAM-020: define the materialization contract and stable protocol
or API types in `../nako`.
