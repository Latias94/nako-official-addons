# OEAM-030 - Host Resolver And Policy Gate

Date: 2026-05-29

## Summary

Implemented the Nako-side runtime materialization route for external
acquisition actions in `../nako`.

The route is `POST /addon/v1/acquisition/materialize`. It uses addon bearer
token identity, then binds the request to a running external acquisition action
task before resolving any host-owned acquisition material.

## Changes

- Added `AddonAppService::materialize_external_acquisition`.
- Added the runtime HTTP route and handler.
- Reused task-run input parsing and addon ownership checks across addon task
  runtime and materialization.
- Validated request schema, job id, declaration id, target ref, runner profile,
  idempotency key, operation, audit ref, and purpose.
- Required materialization requests to match the stored action task payload.
- Resolved `selected_link_ref` as a resource-search-selection intake candidate
  id.
- Resolved `intake_candidate_ref` as an intake candidate id.
- Required candidate library binding and ready/accepted state.
- Returned short-lived materialization responses with safe facts and redacted
  source refs.
- Rejected cloud-drive link types in this runner contract; only `magnet`,
  `ed2k`, and `web` are currently materializable.
