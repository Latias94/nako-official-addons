# OMAFR-020 Journal

Date: 2026-05-23
Status: DONE

## Summary

OMAFR-020 replaced the shallow sidecar configuration shape with a provider-aware
configuration model and made the Addon Manifest derive provider configuration
from runtime truth.

Key changes:

- `Config` now owns provider enablement defaults.
- Manifest configuration schema is generated from `Config`.
- Runtime-supported providers currently expose only `fixture`.
- Routes filter providers by configured enablement.
- Health and diagnostics expose supported, enabled, and disabled provider IDs.
- README, addon README, example manifest, compose, and systemd examples no
  longer advertise unsupported TMDB/Bangumi/Douban settings.
